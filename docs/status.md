does. Kept honest deliberately: a row that says ✅ means there is a test, and a
row that says ❌ means somebody would find it missing by using omt.

Generated by hand and reviewed against `docs/reference/capabilities.md`, which
*is* generated — if the two disagree, the generated one is right.

## Corrected

**"Sessions do not survive a daemon restart" overstated what the docs ask for.**
[07 §5.3](architecture/07-remote-protocol.md) says plainly that *PTYs* do not
survive in v1 and that re-parenting them is deferred — what must survive is the
content, restored as `Orphaned` with a restart offered. That is now implemented,
and the thing I had listed as missing was never in scope.

**A native desktop app was never a documented feature and I put it on this list
myself.** The architecture says "desktop is the same UI with more room"
([01-principles](architecture/01-principles.md)) — the desktop client *is* the
web client on a larger screen, which exists and works. There is nothing to
build here, and listing one as missing was inventing a requirement.

## Not built

Listed because a checklist that only lists what exists is marketing.

| | Why it is not there |
|---|---|
| A speech engine in the box | The `SttProvider` trait, the registry and `voice.providers` are there, and a third party can add an engine without editing omt. **omt ships none.** That is the design rather than a gap: BYOK means the user's audio goes where the user said, on the user's own account, and omt makes no network call until somebody configures one. |
| Codex / opencode protocol sources *connected to a live agent* | The transports are built and tested: `appserver.rs` reads newline-delimited JSON-RPC from a real subprocess, `sse.rs` decodes server-sent events including the cases implementations get wrong. What is not done is registering them as running sources against an installed Codex or opencode and checking the result against those agents' actual output — which needs the agents, not more code. Until that is verified, both stay at the tier their hook path reaches. |
| Native iOS / Android apps | The Swift client compiles and its assertions run (`swift run omt-client-check`), and the Kotlin equivalent is written. What does not exist is either app: no UI, no socket lifecycle, no push registration, and neither has been built against a device. |
