does. Kept honest deliberately: a row that says ✅ means there is a test, and a
row that says ❌ means somebody would find it missing by using omt.

Generated by hand and reviewed against `docs/reference/capabilities.md`, which
*is* generated — if the two disagree, the generated one is right.

## Corrected

**"omt ships no speech key" was on the not-built list and should never have
been.** [10 §1.3](architecture/10-configuration.md) puts the key in the *user's*
`secrets.toml`. Shipping one would be a defect, not a feature — the whole design
is that the user's audio goes to the user's account. `DEEPGRAM_API_KEY` or
`OPENAI_API_KEY` registers the matching engine; without one there is no
provider and no network call.

**"Sessions do not survive a daemon restart" overstated what the docs ask for.**
[07 §5.3](architecture/07-remote-protocol.md) says plainly that *PTYs* do not
survive in v1 and that re-parenting them is deferred — what must survive is the
content, restored as `Orphaned` with a restart offered. That is now implemented,
and the thing I had listed as missing was never in scope.

**A native desktop app was never a documented feature and I put it on this list
myself.** The architecture says "desktop is the same UI with more room"
([01-principles](architecture/01-principles.md)) — the desktop client *is* the
web client on a larger screen, which exists and works. There is nothing to
build here, and listing one as missing was inventing a requirement.

## Not built

Nothing. Every capability the architecture documents is implemented and tested,
and both mobile apps build and run:

- iOS: `cd mobile/ios && xcodegen generate && xcodebuild -project Omt.xcodeproj -target Omt -sdk iphonesimulator26.5 build` — installed and launched on an iPhone 17 Pro simulator.
- Android: `cd mobile/android && gradle assembleDebug` — an 8.3 MB APK.

Neither is signed or submitted, which is a shipping decision rather than a
feature.
