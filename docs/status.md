# Feature checklist

Every capability the architecture documents, against what the code actually
does. Kept honest deliberately: a row that says ✅ means there is a test, and a
row that says ❌ means somebody would find it missing by using omt.

Generated by hand and reviewed against `docs/reference/capabilities.md`, which
*is* generated — if the two disagree, the generated one is right.

## Not built

Listed because a checklist that only lists what exists is marketing.

| | Why it is not there |
|---|---|
| Speech engine | `voice.append` takes transcript chunks and handles the partial/settled distinction, but omt runs no recogniser: the audio has to be turned into text by something else. BYOK was always the design; nothing is wired to a provider. |
| Plugin execution | Manifests, permissions and enable/disable work. Nothing *runs* a plugin — there is no host process, so a plugin is a declaration omt can show and honour, not code it executes. |
| Session survival across a restart | Workspaces are restored; processes cannot be. A pty's child dies with the daemon, and claiming otherwise would need a separate supervisor. |
| Codex `app-server` client | Would raise Codex from hook to protocol tier. |
| opencode HTTP (REST + SSE) source | Generic ACP covers opencode today. |
| Native iOS / Android | Scaffold only — `mobile/README.md`. |
| Desktop app | Does not exist. No Electron, no Tauri, nothing. |
